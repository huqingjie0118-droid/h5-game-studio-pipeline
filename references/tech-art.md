# 游戏技术美术设计模块 (Technical Art Design Module)

> 本文件是 h5-game-studio-pipeline 的**程序性**技术美术方法论，由 `art-director`（技术侧）在 Stage 3（资产生成）与 Stage 4（集成）主路由，`engineering-lead` 配合实现。
> **分工边界**：`systems-mechanics.md` 管"系统层怎么做"（循环/经济/数值），`level-design.md` 管"空间层怎么做"（流程/节奏/遭遇），`narrative-design.md` 管"意义层怎么做"（主题/角色/故事），本文件管**"视觉层怎么做"（资产规格/渲染方案/VFX 实现/性能预算）**。设计侧写"要什么效果"，本文件写"这个效果在 Canvas 2D 里怎么实现、花多少钱、怎么保证不超预算"。
> 与 `asset-gen-spec.md`（生成 prompt）、`asset-mapping.md`（路径映射）、`pitfalls.md`（事故型坑）、`design-principles.md`（质量准线）互补：**本文件管"怎么做对"，它们管"怎么生成、怎么接、别踩什么雷、做到什么标准"。**

---

## 铁律：执行顺序不可逆

```
渲染成本模型（先懂 Canvas 2D 的钱花在哪）
   → 视觉资产技术规格（尺寸/内存/格式，生成前定死）
   → 精灵图集与预烘焙（atlas + 离屏缓存，省状态切换）
   → 无光照氛围方案（预烘焙 lightmap / 混合模式 / overlay）
   → VFX 技术规格（效果→实现→成本矩阵）
   → 美术性能预算表（纹理内存/同屏绘制/粒子/滤镜）
   → 像素 vs HD 双轨（缩放与 DPR）
   → 色彩与可读性技术（sRGB/对比度/无障碍）
   → 移动端约束与降级档位 → 技术美术审查清单
```

任何一条写不清，**不准进入下一条**。技术美术和系统/关卡/叙事一样：先懂"钱花在哪"，再定"资产多大"，最后才谈"效果多炫"——**不懂成本就炫特效 = 在给帧率写遗书**。

## §1 Canvas 2D 渲染成本模型（先懂钱花在哪）

> H5 Canvas 2D 没有 shader、没有 GPU 纹理压缩、没有动态光照——一切视觉效果的"贵/便宜"都遵循下面这套成本模型。**技术美术的所有决策都从这里推导。**

### 成本分级（从便宜到贵）

| 成本 | 操作 | 说明 |
|------|------|------|
| **免费** | 纯数学绘制 | `fillRect` / `strokeRect` / 简单 path / `clearRect`——CPU 侧便宜到可忽略 |
| **便宜** | 1:1 `drawImage` | 绘制与源图同尺寸、无缩放的贴图，走 GPU 上传路径，可大量使用 |
| **中等** | 缩放/旋转 `drawImage` | 带变换的绘制触发采样器开销；**缩放 drawImage 比 1:1 贵 ~2–4 倍** |
| **贵** | 状态切换（source 切换） | 每次换一张源图 = 纹理绑定/状态切换；**同屏换 100 次源 = 100 次切换**（呼应 P25） |
| **很贵** | `ctx.filter` | 每帧滤镜 = 逐像素处理，**任何 filter 都不允许出现在主循环** |
| **天价** | `shadowBlur` / `shadowColor` | 每帧实时阴影/发光 = 多遍渲染，**移动端直接卡死，永久禁用** |
| **可控** | `globalCompositeOperation` 叠加 | additive/multiply 用于光照氛围，但**每层 = 一遍 overdraw，层数必须封顶** |

### 三条推论（技术美术决策总纲）
1. **能预烘焙就不运行时算**：缩放好的图、光晕、阴影、发光——全部在**离线阶段**渲染成成品 sprite，主循环只做 1:1 `drawImage`。
2. **能合图就不散图**：同源连续 `drawImage` 是免费换挡，图集（atlas）把几十张散图合成一张，状态切换从几十次降到 1 次。
3. **能分层就不逐帧画**：静态背景、光照层、远景——预渲染到离屏 canvas，主循环整块贴回（呼应 P11）。

## §2 视觉资产技术规格（Tech Spec —— 生成前定死）

> 🔴 **铁律**：资产规格在 Stage 3 生成**之前**由 tech-art 定死，写进 GDD §10，生成与集成照此执行。**生成后改尺寸 = 重做 + 内存浪费。**

### 尺寸阶梯（全项目唯一，禁止随意开新尺寸）
| 资产类型 | 源尺寸 | 用途 | 说明 |
|----------|--------|------|------|
| 角色立绘/精灵 | 512×512 | 场景内角色 | 实际绘制缩放由代码定，**源图统一 512** |
| 图标（武器/技能/物品） | 256×256 | UI 槽位 | 全部进一个图标图集 |
| 粒子 sprite | ≤128×128 | 特效 | 单张复用，越小越省 |
| UI 面板底图 | 按面板尺寸 | 面板 | 静态，进预烘焙层 |
| 背景/远景层 | 按视口×2 | 视差背景 | 预烘焙分层 |

### 内存预算表（RGBA = 宽×高×4 字节）
| 档位 | 纹理内存总量 | 单张上限 | 目标 |
|------|--------------|----------|------|
| 移动端（默认） | ≤ 64 MB | 2048×2048（16MB） | 低端机可跑 |
| 桌面端 | ≤ 128 MB | 4096×4096（64MB） | 高画质档 |
- **反例**：`"每职业一张 4096² 立绘 × 6 职业"` = 6×64MB = 384MB → 移动端直接闪退。**先算总账再让 AI 生成。**

### 格式与压缩
- 有透明：**PNG**（默认）；大图场景背景可用 **WebP**（有损 90% 质量，体积 -60~70%，需检测浏览器支持，不支持回退 PNG）。
- **禁止**：运行时逐帧解码大图（P09）；位图资源用 JPEG 带透明需求（P07 去背场景）。
- 音频外置、图标合图（§3）。

## §3 精灵图集与预烘焙（Atlas & Pre-bake）

### 3.1 图集规范（Atlas）
- **目标**：把同屏可能同时出现的散图合进 ≤2–3 张图集，主循环 `drawImage` 的 source 切换次数压到个位数。
- **打包规则**：
  1. 按用途分集：`ui.atlas`（图标/面板）、`fx.atlas`（粒子/特效）、`char.atlas`（角色/敌人）——**不要把所有图塞一张**，会撑爆单张上限。
  2. 每集记录 JSON 清单：`{name: {x, y, w, h}}`，集成时代码据此切片（对接 `asset-mapping.md` 的路径约定）。
  3. 空白留边 ≥2px 防采样渗色（相邻帧采样串色）。
- **命名纪律**：生成即按 `design-principles.md` 命名规范（`类型_对象_变体_状态`），合图工具可自动按前缀分组。

### 3.2 预烘焙策略（Pre-bake）
| 预烘焙对象 | 做法 | 省了什么 |
|------------|------|----------|
| 静态背景 | 整场景离屏 canvas 渲染一次，主循环整块 `drawImage` | 每帧几十次绘制 → 1 次 |
| 光照层 | 预烘焙 lightmap（见 §4） | 运行时混合成本 |
| 发光/光晕 | 离线渲染成带 alpha 的成品 sprite | 运行时 `shadowBlur`（天价）→ 1:1 drawImage（便宜） |
| 缩放版本 | 图标/精灵预生成 2–3 档缩放（1x/2x/3x），按需 1:1 绘制 | 缩放 drawImage（中等）→ 1:1（便宜） |
| 视差层 | 每层背景预渲染成独立大图 | 分层逐帧绘制 |

### 3.3 动态层纪律
- 只有**真在动的**才进主循环：玩家/敌人/子弹/粒子/动态 UI。
- 每帧绘制顺序固定：预烘焙背景 → 光照层 → 动态层 → 预烘焙前景/UI——**层序恒定，状态切换可控**。

## §4 无光照氛围方案（Canvas 2D 的光影魔法）

> Canvas 2D 没有实时灯光。要做出"氛围"，靠三层技法：**预烘焙光照贴图 + 混合模式叠加 + overlay 色彩分级**。这是提升美术效果性价比最高的一章——**成本全在离线，运行时几乎免费。**

### 4.1 预烘焙光照贴图（Lightmap）
- **做法**：把场景静态部分渲染到离屏 canvas A（正常），再画一个"光照贴图"canvas B（黑底 + 暖色光源渐变/冷色阴影渐变），每帧：
  ```
  ctx.globalCompositeOperation = 'source-over'; drawImage(A)   // 正常场景
  ctx.globalCompositeOperation = 'multiply';   drawImage(B)   // 光照压暗 + 染色
  ```
- **效果**：火把暖光、洞穴冷暗、黄昏橙调——全部离线画好，运行时 1 次 multiply，成本≈1 次 drawImage。
- **动态光源**（少）：火把闪烁 = 对 B 做整体 alpha 微调，**不重画 B**。

### 4.2 混合模式工具箱
| 模式 | 用途 | 成本 | 纪律 |
|------|------|------|------|
| `multiply` | 暗部、染色、光照贴图 | 1 遍 | 全屏层 ≤1 个 |
| `additive`（lighter） | 发光、火焰、能量 | 1 遍 | **同屏 additive 层 ≤2**，超了 = overdraw 失控（移动端杀手） |
| `source-over` | 常规绘制 | 免费 | 默认模式，绘制完立刻复位 |
- **铁律**：混合模式用完**必须复位**为 `source-over`（呼应 P26 save/restore）；叠加层数进预算表（§6）。

### 4.3 色彩分级 Overlay
- 每张场景一个"氛围 overlay"（渐变图：黄昏橙 / 夜晚蓝 / 危险红），随关卡/节拍切换，alpha 缓动过渡。
- **呼应叙事/关卡节奏**：level-design Pacing Chart 的张力段 + narrative 注入点 → 氛围层跟随变化（战斗 = 暖红增强，喘息 = 冷蓝放松）——**美术氛围 = 节奏的视觉化**。

### 4.4 视差背景
- 2–3 层预烘焙背景，按 `视差系数`（0.2/0.5/0.8）平移，远处层最慢。
- **纪律**：视差层不进主循环逻辑，只做位移合成；层数 ≤3（移动端），防止 drawImage 计数超预算。

## §5 VFX 技术规格（效果 → 实现 → 成本矩阵）

> 对接 `systems-mechanics.md §7`（Juice 规格：要什么感受）。本表补上**怎么实现 + 花多少钱**——两张表合起来才是一个可交付的 VFX 规格。**Stage 3 出资产、Stage 4 实现前，art-director 先填本表。**

| Juice 效果 | 技术实现 | 资产来源 | 运行时成本 | 预算建议 |
|------------|----------|----------|------------|----------|
| 暴击红字/飘字 | FCT 文本 + 放大动画 | 无（文本） | 低 | 池化飘字，≤20 个/屏 |
| 命中顿帧 hitstop | 时间缩放（freeze 60–120ms） | 无 | 免费 | 每击必用，最便宜的爽感 |
| 屏震 | 整体 transform 偏移（衰减） | 无 | 免费 | 高频但幅度小 |
| 粒子（火焰/碎片） | 池化 sprite + additive（火焰） | 单张 ≤128px sprite | 中 | 移动 ≤200 / 桌面 ≤500 |
| 发光光晕 | 预烘焙 alpha sprite + additive | 离线预烘焙 | 中（additive 层） | 同屏 ≤2 个光晕 |
| 光柱/圣光 | 预烘焙梯形渐变 sprite + additive | 离线预烘焙 | 中 | ≤2 个，禁止运行时渐变 |
| 阴影 | 预烘焙椭圆 sprite（**禁 shadowBlur**） | 离线预烘焙 | 低 | 每个动态对象 1 个 |
| 弹道拖尾 | 预烘焙渐变条 sprite + 池化 | 离线预烘焙 | 低 | 走粒子池 |
| 伤害跳变数字 | FCT + 每帧上浮淡出 | 无 | 低 | 池化，复用模板 |
| 场景氛围切换 | overlay 渐变层 alpha 缓动 | 预烘焙 overlay | 免费 | 单层，全屏 |

- **规则**：
  1. **VFX 规格 = Juice 表 + 本表**，缺实现/成本列的不准进 GDD。
  2. **无资产复用**：特效 sprite 全部进 `fx.atlas`，禁止特效散图。
  3. **粒子全池化**（呼应 P22），数量封顶进预算表。
  4. 每个 VFX 标注**平台档位**：`[P] PC / [C] Console / [M] Mobile`——移动端不实现的重效果必须在 GDD 里显式标注降级（见 §9）。

## §6 美术性能预算表（视觉层帧预算）

> 对接 `design-principles.md §三.3`（60FPS = 16.67ms 全系统预算）。本表是**美术资产维度**的预算，Stage 4 集成时逐项核对，**Gate 4 必查**。

| 指标 | 移动端预算 | 桌面端预算 | 超预算动作 |
|------|-----------|-----------|-----------|
| 纹理内存总量 | ≤64 MB | ≤128 MB | 降尺寸/转 WebP/砍图集 |
| 同屏 `drawImage` 次数 | ≤300 次/帧 | ≤800 次/帧 | 合图集/预烘焙静态层 |
| 源图切换次数 | ≤8 次/帧 | ≤16 次/帧 | 强化图集分组 |
| 粒子数 | ≤200 | ≤500 | 砍密度/缩短寿命 |
| additive 混合层 | ≤2 层 | ≤4 层 | 合并光效层 |
| `filter` / `shadowBlur` | **0**（永久禁用） | 0（永久禁用） | 预烘焙替代 |
| 缩放 drawImage | ≤30 次/帧 | ≤80 次/帧 | 预生成缩放版本 |
| 动态文本（FCT） | ≤20 | ≤40 | 池化/复用 |
| 全屏 overlay 层 | ≤1 | ≤2 | 合并为单层渐变 |

- **测量方法**（Stage 4 用）：DevTools Performance 面板抓 10s 主循环，统计每帧 `drawImage` 调用数与 `rendering` 时间；对照上表逐行打勾。
- **反例自查**：`"Boss 战 200 粒子 + 4 个 additive 光效 + 逐帧 filter 扫光"` = 移动端三重超预算（粒子 200 ✓、additive 4 > 2 ✗、filter ✗）→ Gate 4 直接 FAIL，重做 VFX 规格。

## §7 像素 vs HD 双轨（缩放与 DPR）

### 7.1 像素风铁律（对接 design-principles §二.3）
- **1x 制作、放大显示、绝不缩小**；渲染 `imageSmoothingEnabled=false` + 整数倍缩放（呼应 P03）。
- 基础分辨率：像素风 320×180–640×360，角色 16–32px；缩放整数倍（2x/3x/4x），非整数倍 = 模糊。

### 7.2 HD 风规则
- `imageSmoothingEnabled=true`（默认），绘制尺寸 = 源图逻辑尺寸，不随意放大超过 2x（放大即糊）。
- 高 DPI：`canvas.width = cssW * dpr`（dpr 上限 **≤2**，3x 屏强行 2x 省内存），`ctx.scale(dpr,dpr)`（呼应 P04）。
- **动态分辨率**（低端机可选项）：帧时间超预算时降 dpr 档位（2→1.5→1），视觉轻微变糊换帧率——**降档逻辑必须做成开关，不默认开启**。

### 7.3 缩放预生成
- 图标/立绘在离线阶段预生成 1x/2x 两档（进图集），运行时 1:1 绘制，永远不缩放 drawImage（§3.2）。

## §8 色彩与可读性技术（技术侧落实）

> 对接 `design-principles.md §二.4`（色彩可读性优先）。本文件补**技术落地手段**。

1. **sRGB 一致性**：AI 生成图可能带色彩空间标签，统一按 sRGB 处理；不要混入 Display-P3 源图（Canvas 混色会偏）。
2. **对比度可测**：可交互物/关键信息与背景的对比度用工具测（如亮度差 ≥ 阈值），**不只靠肉眼**——不同屏幕色准差异大。
3. **无障碍双通道**：不只用颜色区分（红蓝敌我 → 加形状/图标），呼应 design-principles；技术侧 = 形状层叠加到色层，两者都进图集。
4. **氛围 overlay 与可读性冲突检查**：夜间 overlay 压暗后，**关键 UI/敌人辨识度必须复测**——氛围不能压掉游戏可读性（Boss 战红 overlay + 红色敌人 = 灾难）。
5. **色彩节奏**：每场景 overlay 的色相变化 = 关卡节奏的视觉锚点（§4.3），但同一场景内**同物同色系**保持一致（呼应 design-principles）。

## §9 移动端约束与降级档位（低端机保命）

> H5 游戏一半以上流量来自移动端。**默认按移动端预算设计，桌面端是增强不是默认。**（呼应 design-principles §五）

| 维度 | 移动端纪律 |
|------|-----------|
| 纹理内存 | 总账 ≤64MB（§2），启动只载核心 <2MB，其余 lazy load（呼应 P28） |
| 帧率 | 30FPS 往往够，先保 30 再冲 60；动态降 dpr 是保命开关（§7.2） |
| 中断 | 切后台暂停 + 存档（呼应 P23）；**特效状态一并保存**（粒子中途不炸） |
| 触控 | 交互目标 ≥44×44pt；特效不遮挡触控区（大招特效 + 技能按钮 = 误触源） |
| 电池 | additive/粒子是耗电大户，长驻战斗场景控制密度；后台即休眠 |

**降级档位表**（每档一键切换，进配置）：
```
High   : 全特效 + dpr2 + 粒子上限 500   // 桌面
Medium : 关光晕 + additive≤2 + 粒子 200 // 默认移动端
Low    : 关粒子拖尾 + 关场景 overlay + 粒子 60 + dpr1  // 低端机保帧率
```
- **纪律**：降级**不改变玩法判定**（特效纯视觉），降级只砍视觉效果不砍逻辑——这是技术美术和工程的分界契约。

## §10 技术美术审查清单（Gate 3 / Gate 4 用）

> 与 systems-mechanics §9 / level-design §11 / narrative-design §10 同纪律：**审查在交付前定义"坏长什么样"**。分两个 Gate 执行。

### Gate 3（资产生成后）：资产技术规格审查
- [ ] 所有资产尺寸符合 §2 尺寸阶梯，无随意新尺寸
- [ ] 纹理内存总账 ≤ 预算（移动 64MB / 桌面 128MB），超了已砍或转 WebP
- [ ] 命名符合 `类型_对象_变体_状态`（对接 design-principles + asset-mapping 路径）
- [ ] 图标/特效已规划进图集（§3），无散图
- [ ] 背景/光照/光晕等预烘焙资产已生成（§3.2/§4）
- [ ] VFX 规格表已填：每个效果有实现方式 + 成本 + 平台档位（§5）

## §11 完整示例：视觉技术规格章节（Worked Example：旧秤）

> 用一套完整 GDD 视觉章节演示 §1–§10 怎么落地。**这是格式范本，不是内容答案**——照这个节奏填你自己的游戏。示例延续"旧秤"世界观（idle 修仙 RPG + 拍卖行），与 `narrative-design.md §12` / `level-design.md §13` 同一宇宙。

### §11.1 资产清单与内存总账（§2 落地）

| 资产组 | 张数 | 单张尺寸 | 内存(RGBA) | 目标图集 |
|--------|------|----------|------------|----------|
| 角色立绘 | 4 职业 | 512×512 | 4×1MB = 4MB | char.atlas |
| 敌人精灵 | 8 | 256×256 | 8×0.25MB = 2MB | char.atlas |
| 武器/技能图标 | 24 | 256×256 | 24×0.25MB = 6MB | ui.atlas |
| UI 面板底图 | 6 | 512×256 | 6×0.5MB = 3MB | ui.atlas |
| 特效 sprite | 12 | ≤128×128 | 12×0.06MB ≈ 0.75MB | fx.atlas |
| 背景/远景 | 3 层 | 1280×720×2 | 3×7.4MB ≈ 22MB | 预烘焙独立 |
| 光照贴图 | 3 场景 | 1280×720 | 3×3.7MB ≈ 11MB | 预烘焙独立 |
| **合计** | — | — | **≈ 49MB** | **≤64MB ✓（移动端达标）** |

- **反例对照**：若角色立绘全用 1024² → 4×4MB=16MB 起步，总账直接奔 80MB+ → 移动端闪退。**先算总账再让 AI 生成。**

### §11.2 图集规划（§3 落地）

```
ui.atlas   2048×2048: 24 图标 + 6 面板 + 留边 2px → JSON: {icon_sword: {x,y,w,h}, ...}
char.atlas 2048×2048: 4 立绘 + 8 敌人 + 2x 缩放档（1x/2x 同集）
fx.atlas   512×512:   12 特效 sprite（粒子 64px、光晕 128px、阴影 96px）
```

### §11.3 光照与氛围方案（§4 落地）

| 场景 | 方案 | 运行时成本 |
|------|------|-----------|
| 拍卖行（暖） | 预烘焙 lightmap：烛光暖黄 + 角落冷阴影，multiply 叠加 | 1 次 multiply |
| 野外（日） | 无 lightmap，靠 asset 本身明度 + 视差 3 层 | 3 次 drawImage |
| 副本（冷/危险） | lightmap 冷蓝 + 战斗时红 overlay 渐变（alpha 缓动 0→0.35） | 1 multiply + 1 overlay |
| 火把闪烁 | 动态光源仅 1 个：lightmap 整体 alpha ±0.05 微调 | 免费（不重画） |

### §11.4 VFX 规格表（§5 落地，与 narrative §12 节拍对齐）

| 节拍 | Juice 效果 | 技术实现 | 资产 | 成本 | 平台档 |
|------|-----------|----------|------|------|--------|
| 暴击 | 红字放大 + 顿帧 80ms | FCT 池化 + 时间缩放 | 无 | 低 | [P][C][M] |
| 鉴定秤亮起 | 光晕脉冲 | 预烘焙 glow sprite + additive | fx.atlas#glow | 中 | [P][C][M] |
| 破防 | 进度条碎裂 + 屏震 | 预烘焙碎片粒子 + transform 偏移 | fx.atlas#shards | 中 | [P][C][M] |
| Boss 破防窗口 | 全屏红 overlay + 光柱 | overlay 渐变 + 预烘焙光柱 sprite | 预烘焙 | 中 | [P][C]（M 关光柱） |
| 拍卖落锤 | 金粒子 + 音效 | 池化 30 粒子 + additive | fx.atlas#gold | 低 | [P][C][M] |

### §11.5 降级档位（§9 落地）

```
High  : 全部 VFX + dpr2 + 粒子 500   // 桌面
Medium: 关光柱 + additive≤2 + 粒子 200  // 默认移动
Low   : 关 overlay + 关光晕 + 粒子 60 + dpr1  // 低端机（Boss 战仍可玩，视觉降级不影响判定）
```

## 与 Stage 3 / 4 与各模块的对接

- **asset-gen-spec.md**：生成 prompt 前，先按本文件 §2 定死尺寸与内存总账，再让 `agnes-ai` 出图——规格先行，生成照做。
- **asset-mapping.md**：图集 JSON 清单（§3.1）作为映射的新入口，集成代码按清单切片，路径约定不变。

- **gdd-template.md §10**：资产清单从 3 行路径扩展为"路径 + 技术参数"（见模板），Stage 3 生成前由 art-director 按 §2 填齐。
