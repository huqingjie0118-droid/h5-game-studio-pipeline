# 游戏关卡设计模块 (Level Design Module)

> 本文件是 h5-game-studio-pipeline 的**程序性**关卡空间设计方法论，由 `design-strategist` 在 Stage 2（grill-me / GDD）与 `systems-mechanics.md` 并列主路由。
> **分工边界**：`systems-mechanics.md` 管"系统层怎么做"（循环/经济/数值），本文件管"空间层怎么做"（流程/节奏/遭遇/可读性/环境叙事）。一个 GDD 只有系统没有关卡 = 玩家在"纸面上"玩了一款游戏，工程无从落地。
> 与 `design-principles.md`（质量准线：PASS 长什么样）和 `pitfalls.md`（事故型坑）互补：**本文件管"怎么做"，它们管"做到什么标准"和"别踩什么雷"。**

---

## 铁律：执行顺序不可逆

```
Level Intent → Shape Language → Pacing Arc → Flow Diagram
   → Encounter Design → Navigation Readability → Environmental Storytelling
   → 空间教学阶梯 → Blockout Spec → 关卡 Playtest 失败信号
```

任何一条写不清，**不准进入下一条**。关卡设计和系统设计一样，先有意图再有形状，先有流程再有房间——**没有意图就画房间 = 在填一个没人知道为什么存在的空间**。

**高级用法（§1–§11 是地基，§12–§14 是加速器）**：
- 起步快：从 §12 模式库**挑选组合**空间模块，而不是从零画图（但组合必须过 Level Intent 过滤）；
- 对齐格式：写 GDD 前先看一遍 §13 完整示例关卡，照它的节奏填自己的内容；
- 收尾校验：写完所有章节后跑一遍 §14 联动检查，确保关卡与系统/数值没打架。

## §1 Level Intent（关卡意图 —— 玩家幻想）

- **定义**：用一句话写完 **"玩家走出这一关时，心里应该装着哪个感受"**。
- **时机**：grill-me 确定 Fun Hypothesis 之后、任何布局之前先逼出这句话。写不出 = 这关没有存在的理由，回到全局 Fun Hypothesis 重新推导。
- **反例 vs 正例**：
  - ✗ `"第三章，森林地图"` —— 这是美术外包单，不是意图。
  - ✓ `"玩家在这一关感受'从猎手到猎物'的角色倒转——前半段他追杀精英怪，后半段他发现自己才是被包围的那个"` —— 可推导布局（对称的追/逃结构）、遭遇（敌方增援时机）、叙事（伏笔道具）。
  - ✓ `"这一关让玩家学会'用环境伤害打怪'，并在 Boss 房前被迫综合运用"` —— 可推导教学阶梯和 Boss 房布局。
- **校验**：这句话能推导出 ≥1 个**本关独有、不可复用的布局决策**吗？不能 → 重写。关卡意图必须回答"为什么这关长这样，而不是复制上一关"。

## §2 Shape Language（形状语言）

- **定义**：关卡整体空间拓扑。形状决定玩家对"我正在经历什么"的潜意识判断，必须在画任何房间前选定。
- **选择纪律**：形状由 Fun Hypothesis + 玩法驱动，**不由美术主题决定**。"森林"可以做成线性走廊，也可以做成枢纽——先定形状，再套皮。

| 形状 | 拓扑特征 | 玩家感受 | 适配玩法 | H5 Canvas 2D 范例 |
|------|----------|----------|----------|-------------------|
| **线性 Linear** | 单路径，节点串联 | 推进感、可控的节奏 | 叙事驱动、教学、竞技关卡 | 平台跳跃关、射击关 |
| **枢纽 Hub** | 中央安全区辐射多支线 | 掌控感、选择权 | RPG、进度解锁、任务交付 | 主城 + 各野外地图入口 |
| **开放 Open** | 多路径并行，目标点散布 | 自由感、探索焦虑（需引导） | 探索、收集、生存 | 俯视角生存图 |
| **迷宫 Labyrinth** | 高分支、回路、伪死路 | 迷失感（**仅限刻意设计**） | 解谜、恐怖、隐藏奖励 | 地牢、藏宝图寻宝 |

- **混合形状（合法）**：关卡可以分段混用（如"线性开场 → 枢纽中段 → 线性高潮"），但**每一段的形状必须显式标注**，禁止无意识地来回切换导致玩家失去方向感。
- **关键规则**：
  1. 形状与节奏强绑定——线性适合紧节奏，枢纽必须给喘息，迷宫必须配"玩家知道自己为什么进来"的动机。
  2. 玩家可自由选择 vs 玩家被设计引导——开放形状**不等于放弃引导**，只是引导手段从墙变成光、地形、奖励（见 §6）。

## §3 Pacing Arc（节奏弧线）

- **定义**：把本关玩家体验画成一条**张力随时间变化的曲线**。关卡设计 = 管理张力的工程，不是堆房间的工程。
- **标准弧线**：`Tension（引入）→ Release（释放/喘息）→ Escalation（升级）→ Climax（高潮）→ Resolution（解决/余韵）`。
- **规则**：
  1. 张力**不许平线**——连续 3 个同强度节点（不管多紧张或多平淡）必须重排。
  2. 每次高强度节点后必须有喘息（低强度走廊/奖励区/叙事点），否则玩家"绷断"退游。
  3. 高潮节点前安排**强度阶梯**（如 小→中→大 的遭遇递进），不允许 0→100 跳变。
  4. 与全局 session loop 对齐——单关节奏是 session 张力的一部分，不是独立宇宙。

**Pacing Chart 模板**（GDD 必填，`[PLACEHOLDER]` 纪律同 systems-mechanics §6）：

```
Time   | Activity Type  | Tension | Notes（本段在服务什么意图）
-------|----------------|---------|------------------------------
0:00   | 叙事/探索      | Low     | 环境叙事开场，给出本关动机
1:30   | 遭遇 E01       | Med     | 教学：新机制孤立实例
3:00   | 探索+奖励      | Low     | 岔路奖励，喘息
4:30   | 遭遇 E02-E03   | High    | 机制组合运用（升级）
6:00   | 高潮 E04       | Very High| Boss/本关记忆点
7:00   | 解决           | Low     | 余韵+出口+钩子（下关预告）
```

## §4 Flow Diagram（流程图）

- **定义**：关卡的结构化节点图。先画图，再画房间——**图是设计，房间是图的物理化**。
- **节点标记规范**：

```
[入口 Entry] → [教学 T] → [遭遇 E01] ──→ [岔路 J01] ──→ [主线…]
                                              │
                                              ├─→ [支线奖励 R01]（可选）
                                              │
                                              └─→ [汇合 Merge] → [高潮 E04] → [出口 Exit]
```

| 节点 | 符号 | 定义 |
|------|------|------|
| 入口/出口 | Entry / Exit | 关卡边界 |
| 教学节点 | T | 用空间教机制（见 §8） |
| 遭遇节点 | E+编号 | 战斗（见 §5） |
| 岔路 | J+编号 | 玩家做路径选择 |
| 奖励节点 | R+编号 | 可选内容，**必须可见才成立**（诱惑设计） |
| 汇合 | Merge | 支线回归主线处 |

- **黄金法则（每条岔路）**：**1 条明显的主线 + 1 条可感知的支线奖励**。支线奖励必须从选择点**看得见**（发光宝箱/独特地标），否则玩家不知道岔路存在，等于白做。
- **可读性法则**：主线路径的连续性不能被支线"吸走"——支线出口必须回汇到主线（Merge），不允许支线变成找不到回来的深坑。
- **死路规则**：允许伪死路（小奖励 + 明显折返信号），禁止真死路（无奖励且看起来像入口）。

## §5 Encounter Design（遭遇设计）

- **定义**：每个战斗节点的"空间剧本"。**难度首先由空间决定，数值只是兜底**——位置对了，同数值的怪可以难 3 倍或简单 3 倍。
- **三大硬性要求（缺一即不合格）**：
  1. **Entry Read Time（读时间）**：玩家进入遭遇区时，必须有 ≥1 秒看清"敌人数量、构成、威胁方向"的时间。敌人可以存在，但**必须先被看见再被伤害**——除设计好的伏击（必须有预警信号：脚印、血迹、氛围音乐变化）。
  2. **≥2 种战术选项**：从遭遇入口位置出发，玩家至少有两种可行打法（绕侧翼/压制/卡地形/逐个引），不允许只有"硬刚"一条路。
  3. **Fallback Position（撤退位）**：遭遇区必须有 1 个空间上显而易见的退守位置（门口/高台/掩体群），玩家打不过能撤、能回血、能重组——这是"公平感"的物理来源。
- **表格模板**（GDD 每个遭遇一行）：

| ID | 类型 | 敌数 | 战术选项 | 撤退位 | 服务意图 | 教学点 |
|----|------|------|----------|--------|----------|--------|
| E01 | 教学遭遇 | 2 | 逐个引 / 卡门 | 入口门洞 | 教"引怪" | T1 实例化 |
| E04 | Boss 房 | 1+Boss | 绕柱 / 高空位 / 挡弹幕 | Boss 房门 | 高潮记忆点 | 综合应用 |

- **反例自查**：`"入口即被 5 个敌人包围，无掩体，门在身后关上"` —— 同时违反 1（无读时间）、2（无战术）、3（无撤退位）。这种遭遇只在"玩家已完全掌握系统"的终局关出现一次作为**刻意震撼**，且必须在入场前有明示预警。

## §6 Navigation Readability（导航可读性）

- **定义**：玩家不靠小地图、不靠问路，只靠空间本身就能走对主线的能力。**H5 游戏无小地图是常态，可读性不是可选项，是地基。**
- **核心测试——3 秒出口测试**：玩家进入任意房间后 3 秒内，必须能指出主线出口方向。做不到 = 该房间的引导失败，**用光照/颜色/几何修，不许用箭头贴纸修**。
- **引导工具箱（按优先级）**：
  1. **光照**：主线比支线亮；出口方向的光源是默认最强的引导。
  2. **颜色**：可交互物/出口用环境色对比色（暖光冷底或反之）；同物同色系（呼应 design-principles §二.4）。
  3. **几何**：出口用大开口 + 纵深透视；禁止"看起来像入口的死路"（呼应 §4 死路规则）。
  4. **地标（Landmark）**：远方唯一轮廓（塔/巨树）作为天然路标，Kevin Lynch 式空间锚点。
- **心理学**：**Prospect-Refuge（前景-庇护）**——玩家在"有安全背靠的观察位"感到掌控。每个大型区域入口处放一个"能看到全局、背后有墙"的高地/入口平台，玩家先读图再行动，焦虑减半。
- **可读性检查清单**（GDD 完成时逐项打勾，Gate 2 必查）：
  - [ ] 每个房间 3 秒内能找到主线出口方向
  - [ ] 主线光照强度 > 支线
  - [ ] 无"看起来像出口的真死路"
  - [ ] 岔路处支线奖励可见（诱惑成立）
  - [ ] 大型区域入口有 prospect 观察位
  - [ ] 视觉引导不依赖小地图/箭头贴纸

## §7 Environmental Storytelling（环境叙事）

- **定义**：用道具摆放、磨损痕迹、光照、残骸让玩家**不读一个字**就推断出"这里发生过什么"。每个房间至少一个叙事节拍，**禁止纯装饰的空房间**。
- **三问法**（每个房间问三遍）：
  1. 这个房间在故事里**最后一个人离开时**是什么状态？（决定杂乱/整洁/匆忙）
  2. 房间里的**道具为什么在这个位置**？（翻倒的椅子=逃离；整齐的床=被控制；墙上的划痕=囚禁）
  3. 这个叙事节拍**在服务哪条 Design Pillar / 关卡意图**？（服务不到 → 删，别堆杂物）
- **一致性铁律**：破坏痕迹必须与叙事历史一致——前期被烧毁的村庄，后期不该"复活"成完好状态；同一阵营的建筑风格必须统一。
- **范例（追击关）**：门口洒落的货架 + 半开的门 + 通向深处的血脚印 → 玩家未遇敌已预判"这里有埋伏，且是从我们追的方向来的"——用 3 个道具完成了伏击预警（呼应 §5 的伏击必须有信号）。

## §8 空间教学阶梯（Environmental Teaching）

- **定义**：用关卡空间教新机制，**不用文字弹窗**。任何新机制（钩索/掩体射击/环境伤害）在关卡中必须走完 3 级阶梯，跳级 = 玩家困惑。
- **三级阶梯**：
  1. **T1 孤立实例**：无压力环境下的单独运用（一个高台+一个钩索点，无敌人）。
  2. **T2 低风险应用**：有敌人但无惩罚性后果（敌人很弱/可绕开），逼迫玩家**主动想起**该机制。
  3. **T3 压力下综合**：机制与其他系统组合（钩索+弹幕+时限），作为本关高潮前验证。
- **规则**：
  1. 每个新机制一条独立阶梯，机制之间阶梯不得乱序混用。
  2. T1 必须在玩家"第一次需要这个机制"之前完成——**先教后考，禁止先考后教**。
  3. 旧机制做"复习节点"（低密度复现），防"学会就忘"。
- **反例**：`"Boss 房第一次出现掩体机制，BOSS 弹幕逼玩家躲"` —— T1 缺失，玩家第一反应不是躲而是跑/死。

## §9 Blockout Spec（房间规格 —— 给 Stage 3/4 的交接单）

- **定义**：每个房间的**工程可落地规格**，Stage 4 `engineering-lead` 按此实现，Stage 3 `art-director` 按此出美术。**设计在 GDD 锁定，不留给集成时即兴发挥**（呼应"设计锁定于 blockout"纪律）。
- **房间模板**（每个房间一张）：

```markdown
## Room: <ID> — <名称>

**尺寸**: ~W × D（H5 视口单位，见 §10）
**功能**: 战斗 / 教学 / 叙事 / 奖励
**形状角色**: 属于哪个 Flow 节点（E02 / R01 / T1…）

**掩体/地形**:
- 2× 低掩体（腰高）—— 中位，提供 read time 后掩体
- 1× 可破坏柱 —— 左翼，提供战术选项 B
- 1× 高位 —— 右后方（垫箱可达），撤退位候选

**光照**:
- 主光: 暖色自 <方向>，指向主线出口
- 补光: 冷色自窗，与支线形成对比
- 强调: <颜色> 闪烁于奖励物（诱惑设计）

**入口/出口**:
- 入口: <类型>，进入时可见度如何
- 出口: 入口处 3 秒可见? Y/N（N 必须写明引导手段）

**叙事节拍**: <三问法答案，1-2 句>

**性能注记**: 对象数估算 / 粒子密度 / 是否需对象池（见 §10）
```

## §10 H5 Canvas 2D 关卡设计约束（工程红线）

> 关卡是"设计→工程"的接缝处，以下约束在 GDD 阶段就要生效，**不要在 Stage 4 才发现**。

1. **视口即画布**：H5 关卡必须按**单一视口设计**（移动端竖屏 ~390×844 / 桌面 ~1280×720 起）。单个房间的信息量以"一屏内可读"为上限——屏幕外仍有内容可以，但**方向性引导必须在一屏内成立**（出口可见/光源可见/地标可见）。
2. **性能预算共享**：同屏实体数受 60FPS 预算约束（呼应 design-principles §三.3）。遭遇设计时估算同屏对象峰值：**同屏敌人 + 子弹 + 粒子 ≤ 性能预算**。密集遭遇要么分批进场（波次），要么砍粒子，**不许砍帧率**。
3. **对象池意识**：高频生成物（子弹/掉落/粒子）在 GDD 标注"走对象池"，避免 Stage 4 临时改架构（呼应 pitfalls P22）。
4. **触摸适配**：移动端交互目标 ≥44×44pt；关卡中的可交互点（开关/门/收集物）空间上不能太小，防误触（呼应 design-principles §五）。
5. **地图规模纪律**：H5 关卡是"短而精"的容器——单关建议 **2–4 个核心房间 + 1–2 条支线**，流程时长对齐全局 session loop。**大世界是多个关卡串起来的幻觉，不是一个巨大 Canvas。**
6. **存档/重置点**：关卡中途必须放置自然的"检查点"（存盘点/传送门/区域门），中断恢复友好（来电/切后台，呼应 pitfalls P23）。

## §11 关卡 Playtest 失败信号（关卡版 bad-by 定义）

> 与 systems-mechanics §9 同纪律：**playtest 前先定义"坏长什么样"**。关卡测试需要**观测玩家行为**，不是问"你觉得好不好玩"。

| 系统 | A 失败（重画布局） | B 失败（调参/微调） | C 失败（砍功能） |
|------|--------------------|--------------------|------------------|
| 导航 | 测试者 >30% 在非岔路处停下问"往哪走" | 岔路处犹豫 >5s 但能自己找回 | 缩窄支线/加引导 |
| 节奏 | 连续 2 段同强度 >60s 无变化 | 某一段过长过闷 | 裁掉该段合并下一段 |
| 遭遇 | 测试者 100% 用同一战术/某战术 0 人用 | 死亡 >3 次但能总结对策 | 重排空间（移掩体/换进场） |
| 教学 | T2 测试者想不起该机制（>50%） | 想得起但用错场景 | 回 T1 重教 |
| 环境叙事 | 问"这里发生了什么" 0 人答对 | <70% 答对 | 加/改一个道具讲清 |

- **关卡测试方法**：录像回放看**犹豫点**（停下→环顾→折返）的分布，犹豫点密度即导航失败密度；统计每条战术的使用率，≤1 种战术被用 = 遭遇设计失败，**与数值无关**。

## §12 可复用关卡模式库（Pattern Library）

> H5 小体量游戏不该每次从零画图——把经过验证的空间模块沉淀成"乐高积木"，设计 = 选型 + 组合 + 按 Level Intent 改造。**纪律：模式是起点不是终点，组合必须过 §1 Level Intent 过滤，禁止无脑拼接。**

| 模式 | 用途 | 布局要点 | 常见坑 | 变体 |
|------|------|----------|--------|------|
| **教学走廊** | T1 机制孤立实例 | 单路径、无敌人、机制点可见 | 走廊太长→无聊；机制点不显眼 | 奖励走廊（尾部放小奖） |
| **竞技场** | 中/高潮遭遇 | 环形或矩形、≥3 个掩体位、1 个高位 | 全开放无掩体→无战术；出口太远 | 波次竞技场（分批进场） |
| **追逐段** | 节奏峰值、紧张感 | 单向推进、障碍物延迟、背景崩塌/追赶者 | 追太快→读不了；追太慢→无压力 | 逃离段 / 限时段 |
| **Boss 门厅** | 高潮前哨、心理预期 | 窄通道 → 门 → 开场可见 Boss 房纵深 | 进门即开战→无预期；门厅太空→泄气 | 门厅放补给/存档点 |
| **奖励死角** | 支线诱惑（R 节点） | 从岔路可见、短折返、小奖励 | 奖励不可见→岔路白做；奖励过大→主线失衡 | 隐藏墙后 / 高处跳台 |
| **枢纽广场** | 支线汇聚、喘息、进度反馈 | 中央安全区 + 辐射支线 + 远景地标 | 辐射支线无标识→选择焦虑 | 任务板 / 传送台 / 锻造点 |
| **回声走廊** | 节奏间奏、环境叙事 | 短、无战斗、叙事道具密集 | 过长→玩家想跳过；无叙事→纯赶路 | 记忆回廊 / 风景点 |

**组合示例**（线性动作关）：
```
[教学走廊 T1] → [竞技场 E01] → [回声走廊 叙事] → [追逐段 E02] → [Boss 门厅] → [竞技场 Boss E03]
```
- **程序化生成保底规则**（Infinite/随机地牢用）：程序只能决定**密度与顺序**，不允许决定**质量底线**。三条保底：① 每 N 房间强制插入 1 个手工锚点（教学走廊/Boss 门厅）；② 生成器输出必须过 §6 可读性检查（出口方向、无真死路）；③ 遭遇密度有上下限（同屏峰值 ≤ 性能预算，§10）。程序输出 = 候选，design-strategist 抽检 ≥10% 并有权重掷。

## §13 完整示例关卡（Worked Example：灰烬回廊）

> 用一套完整 GDD 关卡章节演示 §1–§11 怎么落地。**这是格式范本，不是内容答案**——照这个节奏填你自己的游戏。

### §13.1 Intent（意图）
- **Player Fantasy**: "玩家从'追杀者'变成'被猎者'——前半段碾过杂兵建立支配感，中段发现自己的撤退路线被掐断，最后在 Boss 门厅被迫正面迎战曾经不屑一顾的敌人。"
- **记忆点**: 中段岔路 J01 的"断桥"——玩家看到对面是自己来时的路，而桥已塌，第一次意识到回不去。
- **新机制**: 蓄力重击（可破盾）。教学 = 走廊里单独一个盾兵（T1），竞技场混编（T2），Boss 战破盾时机（T3）。

### §13.2 Shape（形状）
- 整体：**线性**（节奏可控，2–3 分钟单关）；分段：线性开场 → 微型枢纽（补给岔路）→ 线性高潮。

### §13.3 Pacing Chart

```
Time   | Activity   | Tension | Notes
-------|------------|---------|------------------------------
0:00   | 教学走廊   | Low     | T1 蓄力重击破盾（孤立盾兵）
1:00   | 回声走廊   | Low     | 环境叙事：烧毁的兵营，服役记录被撕
1:40   | 竞技场 E01 | Med     | T2 混编（2 盾 2 弓），蓄力+走位
2:40   | 岔路 J01   | Low     | 断桥记忆点 + 支线 R01 可见
3:00   | 支线 R01   | Low     | 藏兵营 1 件遗物（诱惑奖励）
3:20   | 追逐段 E02 | High    | 敌人增援追来，单向推进+障碍
4:00   | Boss 门厅  | Med     | 门厅补给 + 存档 + 远景 Boss 房
4:30   | Boss E03   | Very High| 记忆点：Boss 是开头那个"跑掉的盾兵"
5:30   | 解决       | Low     | 出口 + 下关钩子（远处城火光）
```

```
                                          └──→ [R01 遗物] ──→ [Merge 于追逐段起点]
```

|----|------|------|----------|--------|----------|--------|

| E03 | Boss 门厅战 | 1 Boss（盾兵统领） | 破盾窗口输出 / 绕柱躲突进 / 高空台躲横扫 | Boss 房门（战前门厅） | 记忆点+高潮 | T3 破盾时机 |

### §13.6 可读性自查（勾选）
- [x] 每个房间 3 秒内指出出口（教学走廊出口有暖光；竞技场出口是唯一大门）
- [x] 主线比支线亮（支线 R01 冷光，主线暖光）
- [x] 无假出口（Boss 门厅的"来路"是锁死的门）
- [x] 岔路奖励可见（R01 遗物在走廊尽头发光）
- [x] 入口有 Prospect 位（竞技场入口平台可见全场）
- [x] 引导全靠光照/几何（无小地图）

### §13.7 环境叙事节拍
- **教学走廊**：撕毁的服役记录 + 丢弃的盾 → "这里曾有一支军队，被清走了"（为 Boss 是幸存者埋伏笔）。
- **岔路断桥**：断裂的桥面 + 对岸自己的脚印 → 记忆点，玩家意识到"回不去了"。
- **Boss 门厅**：墙上的盾阵独缺一面 → 指向 Boss 手里的那面盾，闭环叙事。

## §14 关卡 × 系统 × 数值联动检查（Cross-Check Interface）

> **关卡设计不是孤岛**。空间层与系统层（systems-mechanics.md）必须对账，否则 GDD 各章节自相矛盾。以下检查在 **Gate 2 前必跑**——两类模块各自 PASS 但互相对不上 = GDD 整体 FAIL。

| # | 检查项 | 空间侧（level-design） | 系统侧（systems-mechanics） | 通过标准 |
|---|--------|------------------------|-----------------------------|----------|
| 1 | **遭遇强度 ↔ DPS 表** | E01 设计"4 敌同屏" | §6 规则3 DPS 工作表 | 每个遭遇的敌血量总和 ∈ 玩家 DPS × [可击杀时间区间]；同屏峰值 ≤ 性能预算（§10） |
| 2 | **奖励投放 ↔ Sources/Sinks** | R01 掉落"1 件遗物" | §5 账本：遗物对应资源有 sink | 关卡奖励产出写入 Sources，且有对应 Sink，不产生新通胀 |
| 3 | **Boss 战 ↔ 数值验证** | E03 设计"破盾窗口" | §6 规则3 玩家可死/可杀时间 | Boss 血量 = 玩家 DPS × [目标战斗时长]；Boss 伤害 = 玩家 HP × [目标死亡时间占比] |
| 4 | **教学阶梯 ↔ 机制解锁** | T1/T2/T3 节奏 | §4 机制活检、机制解锁顺序 | 关卡教学的机制顺序 == 系统解锁顺序，先教后考，禁止先考后教 |
| 5 | **节奏 ↔ Session Loop** | Pacing Chart | §3 三层核心循环（session） | 单关时长 ∈ session 时长预算；关卡高潮 == session 目标达成点 |
| 6 | **难度 ↔ 心流曲线** | 追逐段强度 | design-principles §一.4 心流 | 张力峰值处数值难度同步封顶，双高不同时叠加（空间+数值双高压 = 挫败） |

**对账模板**（GDD 收尾时填）：

| 遭遇 ID | 敌总血量 | 玩家 DPS | 预估击杀时间 | 预算区间 | 结果 |
|---------|----------|----------|--------------|----------|------|
| E01 | 4×120 | 180 | 2.7s | 2–4s | ✓ 通过 |
| E03 | 1500 | 180 | 8.3s | 8–12s | ✓ 通过（破盾窗口计入） |

- **反例自查**：`"Boss 血量 = 玩家 DPS × 30s，但关卡布局没有任何拖延手段"` —— 空间侧没给玩家"活着拖 30 秒"的资本（掩体/窗口），数值侧自洽但空间侧崩溃 = 联动检查抓出来的典型 GDD 病。
