## 一、游戏设计（Stage 2 · GDD 质量 · 准线/PASS 长什么样）

> 本节约等于**质量准线**（Gate 2 看这些是否 PASS）。**怎么严谨地设计**见 `references/systems-mechanics.md`（系统/机制/数值）、`references/level-design.md`（关卡空间/流程/遭遇）、`references/narrative-design.md`（叙事/角色/对话）、`references/tech-art.md`（资产规格/渲染方案/VFX/预算）与 `references/engine-optimization.md`（引擎架构/逻辑物理/内存/加载/性能流程）。六文件互补：本文件管"做到什么标准"，systems-mechanics.md 管"系统怎么做"，level-design.md 管"关卡空间怎么做"，narrative-design.md 管"叙事意义怎么做"，tech-art.md 管"视觉层怎么做"，engine-optimization.md 管"引擎层怎么跑（性能/帧率/加载）"。

### 1. 30 秒核心循环测试
每个游戏必须有一个"好玩的 30 秒循环"：**行动 → 反馈 → 奖励 → 重复**。
- RPG 范例：探索 → 战斗 → 升级 → 换装。
- grill-me 拆创意时，先逼出这条循环，再谈系统。循环不成立，后面都是空中楼阁。

### 2. 玩家类型（Bartle）
| 类型 | 驱动力 | 设计落点 |
|------|--------|---------|
| Achiever | 目标/完成 | 成就、里程碑、排行 |
| Explorer | 探索/秘密 | 隐藏区域、彩蛋、世界观 |
| Socializer | 交互/社群 | 公会、交易、聊天 |
| Killer | 竞争/支配 | PvP、Boss 首杀、竞技 |

→ GDD 应覆盖至少两类驱动力，避免只服务一类。

### 3. 奖励节奏（Reward Schedules）
- **固定**：可预期（里程碑奖励）
- **可变**：成瘾性（掉落/Loot）
- **比率**：努力型（刷本）
→ 经济系统（如拍卖行 gold sink）要混用，单用一种易疲劳或易爆。

### 4. 心流与难度
太难→挫败退游；太易→无聊退游；刚好→心流。
→ 难度应**动态/可选/无障碍**三选驱动；早期给"胜利钩子"快速上头，再渐增挑战，强度间留喘息。

## 二、美术与素材管线（Stage 3 · 生成 / Stage 4 · 集成）

### 1. 命名规范（强约束，直接决定集成能否自动化）
```
[type]_[object]_[variant]_[state].[ext]
例：spr_player_idle_01.png   tex_stone_wall_normal.png
```
→ 与本 skill `asset-mapping.md` 的约定对接（职业 `CLASSES[key].frontImg`、武器 `assets/weapons/<wType>.png`、技能 `art-app/assets/icon_<name>.png`）。生成脚本按此命名，集成零手工映射。

### 2. 文件夹结构
```
assets/
├── characters/{player,enemies}/
├── environment/{props,tiles}/
├── ui/  effects/  audio/
```
→ 生成时按此落盘，避免"图找到了但路径对不上"（呼应 pitfalls P06）。

### 3. 像素美术铁律
- **1x 制作、放大显示，绝不缩小**（缩小必糊）。
- 渲染 `imageSmoothingEnabled=false` + 整数倍缩放（呼应 P03）。
- 基础分辨率：像素风 320×180–640×360，角色 16–32px；移动/桌面 HD 128–256px。

### 4. 色彩可读性优先
- 层级：重要元素要"跳"出来；一致性：同物同色系；上下文：颜色在不同背景读法不同。
- **无障碍**：不要只靠颜色区分（如红蓝敌我外加形状/图标）；暗底/亮底都要测。

### 5. 动画帧数参考
| 动作 | 帧数 | 感觉 |
|------|------|------|
| 待机呼吸 | 4–8 | 微妙 |
| 走/跑 | 6–12 / 4–8 | 顺/冲 |
| 攻击 | 3–6 | 脆快 |
| 死亡 | 8–16 | 戏剧 |

## 三、架构与性能（Stage 4 · 工程实现）

### 1. 游戏循环（Game Loop）
```
INPUT（读操作）→ UPDATE（固定步长处理逻辑）→ RENDER（插值绘制）
```
- 逻辑固定步长（如 50Hz），渲染尽量快，状态间插值保平滑（呼应 pitfalls P21）。

### 2. 架构模式选择
| 模式 | 用于 | 例 |
|------|------|-----|
| 状态机 | 3–5 离散状态 | 玩家 Idle→Walk→Jump |
| 对象池 | 高频生成/销毁 | 子弹、粒子 |
| 观察者/事件 | 跨系统通信 | 血量→UI |
| ECS | 上千同类实体 | RTS 单位 |
| 命令 | 撤销/回放/联机 | 输入录制 |
| 行为树 | 复杂 AI | 敌人决策 |

→ **默认从状态机起步**，性能真不够再上 ECS；输入抽象成"动作"而非原始按键（jump=Space/手柄A/触摸），便于多端/重绑。

### 3. 性能预算（60 FPS = 16.67ms）
| 系统 | 预算 |
|------|------|
| 输入 | 1ms |
| 物理 | 3ms |
| AI | 2ms |
| 逻辑 | 4ms |
| 渲染 | 5ms |
| 缓冲 | 1.67ms |

优化优先级：**算法 → 批处理 → 池化 → LOD → 裁剪**（呼应 pitfalls P24/P22/P25）。

### 4. 通用反模式
| 别做 | 该做 |
|------|------|
| 每帧更新一切 | 事件/脏标记 |
| 热循环里 new 对象 | 对象池 |
| 啥都不缓存 | 缓存引用 |
| 不 profile 就优化 | 先量再改 |
| 输入混逻辑 | 抽象输入层 |

## 四、联机专项（Sprint 3 · 服务端权威战斗）

### 1. 服务端权威（唯一真相源）
```
客户端："我打中了敌人"
服务端：校验 → 弹道真命中？玩家状态合法？时序可能？
```
→ 速度（防加速）、视线（防自瞄）、物品归属（防复制）、隐藏数据不发送（防透视）。

### 2. 反作弊映射
| 作弊 | 预防 |
|------|------|
| 加速 | 服务端校验移动速度 |
| 自瞄 | 服务端校验视线 |
| 物品复制 | 服务端拥有库存 |
| 穿墙/透视 | 不发送隐藏数据 |

### 3. 延迟补偿
- **预测**：客户端预测自身/他人动作
- **插值**：平滑远端玩家
- **协调**：纠正误预测
- **延迟补偿**：为命中判定回滚
→ 默认"输入同步 + 插值渲染 + 增量 + AOI"（呼应 pitfalls P29/P30）。

### 4. 网络预算
- 位置 20–60Hz；血量/背包按变更发；聊天按发送发。
- 带宽手段：增量压缩、量化降精度、兴趣区域（AOI）只同步邻近。

## 五、移动端（Stage 4/5 · 适配）
- 触摸目标 ≥ 44×44pt，带视觉反馈；避免精确时序要求。
- 支持横竖屏（或明确一种并提示）；`touch-action: none` 防误滚动。
- 中断（来电/切后台）必须暂停并保存（呼应 pitfalls P23/P27）。
- 30 FPS 往往够；暂停时休眠省电；暗色模式省 OLED 电。

> 记住：好玩是迭代出来的，不是纸上设计出来的。先原型快跑，再打磨。
